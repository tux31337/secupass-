# Architecture Decision Records

## 철학
v1은 “출시 가능한 단답형 모바일 학습 앱”을 우선한다. 서버, AI 채점, 서술형 같은 큰 기능보다 빠른 문제 풀이, 명확한 대소문자 채점, 오답 복습 경험을 먼저 완성한다. 저작권과 앱 심사 리스크가 있는 기능은 권리와 운영 구조가 준비될 때까지 제외한다.

---

### ADR-001: Expo + React Native 선택
**결정**: 모바일 앱은 Expo + React Native + TypeScript로 만든다.

**이유**:
- iOS와 Android를 동시에 목표로 할 수 있다.
- 현재 목표는 웹사이트가 아니라 스토어 배포 가능한 모바일 앱이다.
- Expo EAS Build/TestFlight/Google Play 내부 테스트 흐름을 사용할 수 있다.
- TypeScript로 문제 데이터, 채점 로직, 학습 기록 타입을 엄격하게 관리할 수 있다.

**트레이드오프**:
- 기존 정적 웹 UI는 그대로 재사용하지 않는다.
- 네이티브 앱 품질을 위해 모바일 UI를 새로 구성해야 한다.

### ADR-002: v1은 단답형 전용 앱
**결정**: v1에는 단답형 문제만 포함한다. 서술형 문제와 rubric 채점은 v2 이후로 미룬다.

**이유**:
- 단답형은 자동 채점 기준이 명확해 첫 출시 품질을 관리하기 쉽다.
- 모바일에서 짧게 풀고 바로 채점하는 경험과 잘 맞는다.
- 문제 수를 빠르게 늘릴 수 있다.
- OpenAI API나 서버 없이도 충분한 MVP 가치를 제공한다.

**트레이드오프**:
- 서술형 대비와 부분 점수 학습은 v1에서 제공하지 않는다.
- 추후 서술형을 추가할 때 타입, 화면, 채점 결과 UI를 확장해야 한다.

### ADR-003: v1은 백엔드 없는 오프라인 앱
**결정**: v1에는 로그인, 클라우드 동기화, 서버 API를 넣지 않는다.

**이유**:
- 초기 출시 범위를 줄이고 앱 심사와 개인정보 부담을 낮춘다.
- 학습 기록은 기기 로컬 저장으로도 MVP 가치를 제공할 수 있다.
- 백엔드 선택 전에도 문제 풀이, 채점, 오답노트 경험을 완성할 수 있다.

**트레이드오프**:
- 기기 간 동기화가 없다.
- 앱 삭제 또는 기기 변경 시 학습 기록이 사라질 수 있다.
- v2에서 계정/동기화를 추가할 때 데이터 마이그레이션이 필요할 수 있다.

### ADR-004: OpenAI API 채점은 v2 이후로 연기
**결정**: v1에는 OpenAI API 기반 채점이나 첨삭을 넣지 않는다.

**이유**:
- v1이 단답형 전용이면 AI 채점이 필요하지 않다.
- API 비용, 서버 운영, 개인정보 고지, 장애 처리 부담을 피할 수 있다.
- 모바일 앱에 API 키를 넣는 위험을 원천 차단한다.

**트레이드오프**:
- 사용자는 v1에서 서술형 첨삭을 받을 수 없다.
- v2에서 AI 첨삭을 추가하려면 백엔드와 Structured Outputs 스키마 설계가 필요하다.

### ADR-005: 기출 원문 미수록, 재구성 문제 우선
**결정**: 권리 확보 전에는 기출 원문과 원문 해설을 출시 앱에 포함하지 않는다. v1은 기출 경향 기반 재구성 단답형 문제만 포함한다.

**이유**:
- 원문 수록은 저작권과 앱 심사 리스크가 크다.
- 자체 재구성 문제는 학습 가치를 제공하면서 법적 리스크를 낮춘다.
- 나중에 권리가 확보된 콘텐츠만 `licenseRef`와 함께 추가할 수 있다.

**트레이드오프**:
- 사용자가 기대하는 “기출 원문 그대로” 경험은 v1에서 제공하지 않는다.
- 문제 제작 품질 관리가 중요해진다.

### ADR-006: 문제 데이터에 라이선스 상태를 포함
**결정**: 모든 문항은 `sourceType`을 가지고, 원문 계열 콘텐츠에는 `licenseRef`를 필수로 둔다.

**이유**:
- 콘텐츠 권리 상태를 코드 리뷰와 테스트에서 확인할 수 있다.
- 출시 전 실수로 원문 콘텐츠가 들어가는 것을 막을 수 있다.
- 향후 공식 공개 자료나 라이선스 콘텐츠를 구분해 관리할 수 있다.

**트레이드오프**:
- 문제 데이터를 작성할 때 필드가 늘어난다.
- 콘텐츠 관리 규칙을 지속적으로 지켜야 한다.

### ADR-007: 단답형 대소문자 정책을 문항별로 명시
**결정**: 단답형 정답 후보마다 `caseSensitive` 값을 반드시 둔다.

**이유**:
- `/etc/passwd`, `chmod` 같은 경로와 명령어는 대소문자 구분이 필요하다.
- `SQL Injection`, `VPN`, `XSS` 같은 일반 보안 용어는 대소문자 차이가 답의 의미를 바꾸지 않는 경우가 많다.
- 사용자에게 오답 이유를 명확하게 설명할 수 있다.

**트레이드오프**:
- 문제 작성자가 각 정답 후보의 정책을 신중히 결정해야 한다.
- 애매한 용어는 콘텐츠 리뷰 기준이 필요하다.
